# 追加実験 v5 の仮説と判定基準 ― 実行前に固定

作成：2026-11-23（v5 の API 実行前）。本書の SHA-256 を `results_v5/run_meta.json` に記録する。実行後の記述は末尾の「実行後の追記」節にだけ書く。

## 背景と問い

v4 では、Haiku の予測を Opus に検証させた値で振り分けると、目標90%に必要なレビュー率が 48.6% から 24.8% に下がった（事前登録の弱い形を満たす）。探索的には、この構成の1件当たり総コスト（33.3円）が Opus 単独（39.5円）より低かったが、差の区間は計算していなかった。

v5 では、**運用構成どうしの総コスト比較**を事前登録して確かめる。あわせて、検証を一部の案件に絞って費用を下げる方法と、v4 の結果の再現を確かめる。

## データ

- dev：v2〜v4 と同じ500件（Opus による Haiku・Sonnet の検証は v4 で取得済み）。
- test：BANKING77 の test から新たに500件を層別抽出する。v1〜v4 の test（計1,700件）とは重複させない。シード 20261127。
- モデル・プロンプト・生成設定・検証プロンプトは v4 と同じ。

## 比較する運用構成（すべて事前に定義）

各構成は「誰が答えるか」と「何で人間に回すかを決めるか」の組。しきい値は開発データで δ=0.05 の方法で選ぶ（v2〜v4 と同じ）。

| 記号 | 構成 | 答える | 振り分けの信号 | API 費用 |
|---|---|---|---|---|
| P_opus | Opus 単独 | Opus | Opus の自己申告 | Opus の分類 |
| P_sonnet | Sonnet 単独 | Sonnet | Sonnet の自己申告 | Sonnet の分類 |
| P_haiku | Haiku 単独 | Haiku | Haiku の自己申告 | Haiku の分類 |
| P_hv | Haiku＋Opus 検証（全件） | Haiku | Opus が Haiku の予測を検証した確率 | Haiku の分類＋Opus の検証（全件） |
| P_hg | Haiku＋Opus 検証（一部） | Haiku | Haiku の確信度がゲート値 g 未満の案件だけ Opus が検証し、その確率を使う。検証しない案件は「1＋Haiku の確信度」とし、検証した案件より後にレビューへ回す | Haiku の分類＋Opus の検証（g 未満の案件のみ） |
| P_sv | Sonnet＋Opus 検証（全件） | Sonnet | Opus が Sonnet の予測を検証した確率 | Sonnet の分類＋Opus の検証（全件） |

- ゲート値 g：開発データにおける Haiku の自己申告確信度の中央値。データを見て変えない。
- P_hg の検証費用は、実際に検証した案件の費用だけを数える（検証自体は全件取得するが、使わない分は費用に入れない）。
- 1件当たり総コスト ＝ API 費用（実費、円換算）＋ レビュー率 × 133.3円（既定：4,000円/時・2分、1ドル150円）。

## 仮説と判定基準

主分析の条件：目標信頼性 Y=0.90、a_h=1.00、δ=0.05。総コストの区間は、開発・最終評価の両方を1,000回再標本化し、毎回すべての構成のしきい値を選び直すブートストラップで求める（同じ再標本を全構成に使う）。判定は「支持」「不支持」「判定保留」のいずれか。

### H1（主仮説）　安いモデル＋強い検証は、強いモデル単独より総コストが低い
**判定**：P_hv − P_opus の1件当たり総コストの差の95%区間が0未満なら支持。0より大きい側に有意なら不支持。それ以外は判定保留。

### H2　安い構成でも保証は保たれる
**判定**：P_hv が最終評価データで適格（片側95%下限 ≥ 0.90）であり、かつブートストラップで適格になる割合が90%以上なら支持。適格でなければ不支持。適格だが割合が90%未満なら判定保留。

### H3　検証を一部に絞っても、レビュー率はほとんど増えない
**判定**：P_hg − P_hv のレビュー率の差の95%区間の上端が +5pt 未満で、かつ P_hg の1件当たり総コストの点推定が P_hv 以下なら支持。区間の下端が +5pt を超えれば不支持。それ以外は判定保留。

### H4　v4 の結果（Haiku）は新しいデータでも再現する
**判定**：P_hv − P_haiku のレビュー率の差の95%区間が0未満なら支持。0より大きい側に有意なら不支持。それ以外は判定保留。

### H5　Sonnet でも、Opus の検証で必要レビュー率が下がる
**判定**：P_sv − P_sonnet のレビュー率の差の95%区間が0未満なら支持。0より大きい側に有意なら不支持。それ以外は判定保留。

## 費用の見積もり

新規呼び出しは、test の分類 3モデル × 500件＝1,500件と、Opus による検証（Haiku・Sonnet の予測）2 × 500件＝1,000件で、計2,500件。v4 の実績単価から約 $2.5。全実験の累計は約 $23 で、承認済みの上限 $30 に収まる見込み。

### 解釈についての注記（事前登録外）

1. **H1 の点推定とブートストラップ平均のずれ**：Opus 単独の点推定（37.3円）は、ブートストラップ平均（28.8円）より高い。Opus の自己申告は値が粗く、実際のデータではしきい値が1段高い側（0.70）で選ばれたためと考えられる。点推定だけを見ると「安い構成のほうが16%安い」と言えてしまうが、しきい値選定の揺れを含めると差は示せない。
2. **一部検証が効かなかった理由**：Haiku の誤答104件のうち26件は、Haiku 自身の確信度が0.80以上だった（検証の対象外）。検証しない案件を後回しにする規則では、目標に届くまでしきい値が検証しない領域に入り込み、結果は Haiku 単独と同じしきい値（確信度0.82未満をレビュー）になった。**弱いモデルが自信を持って間違える案件こそ、強いモデルの検証が必要**で、弱いモデルの確信度で検証対象を絞ると効果が失われる。
3. **v4 の再現**：Opus による Haiku の検証の AUROC は 0.951（v4 は 0.949）、必要レビュー率の低下も同程度だった。v4 の主な結果は新しいデータで再現した。
4. **Sonnet＋Opus 検証**（探索的）：点推定では6構成の中で最も安く（24.6円）、人件費・レビュー時間を変えた12通りのすべてで1位だった。ただし Opus 単独との差は −3.0円（−16.5〜+10.2）で、差は示せない。
5. **総コストの順位は感度分析で変わらなかった**（点推定）：Sonnet＋Opus 検証 < Haiku＋Opus 検証 < Sonnet 単独 < Opus 単独 < Haiku 単独 < Haiku＋Opus 検証（一部）。API 費用（最大0.34円）がレビュー費用に比べて小さいため、順位はほぼ必要レビュー率で決まる。

### 事後の確認（2026-11-23 追記、事前登録外）

実行後に、結論の頑健さを API 費用なしで確かめた（`python -m ready_eval --config config_v5.yaml robustness`、結果は `results_v5/robust_*.csv`）。上の判定は変えない。

1. **a_h を変えた場合**：a_h=0.90（論文の主仮定）では、目標90%・95%はどの構成でも dev の段階で達成できなかった。a_h=0.95・目標90%では全構成が適格で、順位は a_h=1.00 と同じだった。
2. **目標を変えた場合**（元の dev、a_h=1.00、主分析と同じ選定込みブートストラップ）：P_hv − P_opus の総コスト差は、目標85%で +12.0円（+0.3〜+19.5）で Opus 単独のほうが有意に安く、目標95%で −2.7円（−11.5〜+9.6）だった。H1 の「判定保留」は「同程度」を意味しない。
3. **人間が AI の誤答を見逃す場合**：AI の誤答を直せる確率を0.8とすると、目標90%での必要レビュー率は P_opus 27.8%、P_sv 29.6%、P_hv 50.0%、P_haiku 90.6% になり、最も安い構成が P_sv から P_opus に入れ替わった。
4. **dev を入れ替えた場合**：v4 の test 500件（v5 と重複なし）を dev にすると、P_hv − P_haiku の必要レビュー率の差は目標85%・90%・95% で −18.2pt（−23.8〜−13.6）・−20.8pt（−32.6〜−6.4）・−22.6pt（−40.4〜−16.0）で、H4 の結論は保たれた。P_hv − P_opus の総コスト差は目標90%で −1.3円（−14.7〜+12.3）で、元の dev と点推定の向きが変わった。
5. **H4 の「再現」の範囲**：v5 の dev は v4 と同じ500件で、P_hv・P_haiku のしきい値も v4 と同じ（0.60・0.82）だった。H4 は新しい test での再現である。
6. **v4 の 48.6%→24.8% の信号**：v4 の主仮説 H3 は組み合わせ信号（自己申告・Opus の検証・他モデル一致の平均）での値で、Opus の検証だけなら 25.2% だった。v5 の P_hv は Opus の検証だけを使っている。
