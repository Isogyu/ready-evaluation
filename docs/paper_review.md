## 1. 何を問題にしているか

従来のエージェント評価（能力ベンチマーク）は「エージェントが単独でタスクをこなせる割合」を測る。論文は、企業導入の判断にはそれでは足りないと主張する。導入判断に必要なのは次の3点である。

1. 人間とAIを組み合わせた系が、要求される信頼性に達するか
2. そのとき、どれだけ人間の監督（レビュー）が要るか
3. その運用コストが許容できるか

## 2. READY の枠組み

READY は「エージェント」「ワークフロー」「監督方針の候補」を入力に取り、3段階で評価する。

| 段階 | 内容 | 使うデータ |
|---|---|---|
| 1. ワークフロー評価 | エージェントを実行し、各ケースの成否 u と確信度 s を記録 | 全ケース |
| 2. 監督方針の最適化 | 目標信頼性 Y を満たす方針のうち、コスト最小のものを選ぶ | 開発用 |
| 3. Deployment Qualification | 方針を固定し、保留データで信頼性の片側信頼下限が Y 以上かを判定 | 保留用 |

出力は「デプロイメントプロファイル」（信頼性・監督負荷・コスト・適用範囲と仮定）。

### 2.1 主な定義（論文の式番号）

| 量 | 定義 |
|---|---|
| 自律カバレッジ c(τ) | Pr(s ≥ τ)（Eq.14） |
| レビュー率 e(τ) | 1 − c(τ)（Eq.15） |
| 採用分の成功率 a(τ) | Pr(u=1 \| s ≥ τ)（Eq.16） |
| レビュー経路の成功率 a_h | 人間に回したケースが正しく処理される確率。**仮定値**（主分析は 0.90） |
| 信頼性 R(τ) | c·a + (1−c)·a_h（Eq.17–18） |
| コスト C(τ) | k_m + k_h·e(τ)（Eq.19）。k_m・k_h が一定ならコスト最小 ＝ レビュー率最小 |
| しきい値の選び方 | 開発データで R̂_dev ≥ Y + δ を満たすうち最もカバレッジが大きいもの（Eq.45）。δ = 0.05 |
| 適格判定 | 採用分に Clopper–Pearson の片側95%下限を付け、a_h は固定値として足し合わせた下限が Y 以上なら適格（§5.5） |

論文は、δ を入れないと選んだ方針のうち適格になるのは 46% だけで、δ=0.05 を入れると 95% になると報告している（§5.5）。開発データでしきい値をぴったり合わせると選択バイアスで保留データで落ちやすい、というのが δ の理由である（§5.2）。

## 3. 論文の実験と結果

- 題材：CliniCARE-Bench（電子カルテに対する臨床監査、4値判定）750件。開発・保留に375件ずつ、1回だけランダム分割。
- 対象：16システム（Claude Code・Codex・Gemini CLI・opencode と各モデルの組み合わせ）。
- 確信度：各システムが報告書に百分率で書いた自己申告値を 0〜1 に換算。キャリブレーション（ECE等）は報告していない。論文は「確信度が校正済みの確率である必要はない」と明記している（§6.4）。

主な結果（論文の数値）：

1. **正答率がほぼ同じでも必要なレビュー率が違う。** Codex GPT-5.4（自律成功率 72.8%）と Claude Code Sonnet 5（72.5%）は、Y=0.76 を満たすのにそれぞれ 39.2% と 29.6% のレビューを要した。**両者とも適格**である。
2. 自律成功率と、確信度による誤り検出能力（AUROC）の相関は ρ = −0.12 でほぼ無関係。一方 AURC と自律成功率の相関は ρ = −0.80。
3. GLM-5.2 はレビュー率が最小（10.9%）で点推定は目標を超えたが、片側下限 0.725 が Y=0.76 に届かず不適格。
4. Gemini-3.1-Pro は 100% レビューでしか適格にならず、論文は「デプロイではない」としている。
5. a_h = 0.90 のとき、「観測したすべてのカバレッジで採用分の成功率が a_h を下回っていた」ため、どの方針も信頼性 0.90 を超えなかった（Figure 3 キャプション、§5.1）。これは**データ上の観察**であり、一般的な上限ではない。R − a_h = c(a − a_h) なので、採用分の成功率 a が a_h を上回れば R は a_h を超える。**本実験ではこれが起きた**（例：Opus 5.5 で a_h=0.90、Y=0.90 のとき信頼性 0.956）。
6. 金額のコスト値（k_m・k_h の数値）は論文のどこにも出てこない。コストに関する結果はすべてレビュー率で示されている。

## 4. 新規性と従来の評価との違い

| 観点 | 従来の能力ベンチマーク | READY |
|---|---|---|
| 評価対象 | エージェント単体 | 人間＋エージェントの系と監督方針の組 |
| 主指標 | 正答率・成功率 | 目標信頼性を満たすのに必要なレビュー率（とコスト） |
| 確信度 | 使わない、または校正の指標として見る | レビュー振り分けの信号として使う。順位付けの能力が重要 |
| 統計的主張 | 点推定が中心 | 保留データでの片側下限による適格判定 |
| 方針の選び方 | ― | 開発データで決めて固定し、保留データで1回だけ検証 |

選択的予測（selective prediction）やリスク・カバレッジ曲線は既存の考え方である。論文の新しさは、それを「導入判断の手続き」として、仮定（a_h）・安全余裕（δ）・保留データでの判定までまとめて定式化し、16システムで示した点にある。

## 5. 論文が認める限界

- 実証は、完了後に採用かエスカレーションかを決める設定、かつ1ワークフローのみ。
- a_h は仮定であり実測していない。すべての判定は a_h の値に依存する。
- 分布シフト下での保証はない。導入後の監視や再判定は対象外。
- 開発・保留の分割は1回のみ。
- 主目的は2値の成否で、テールリスク制約は評価していない。
